# Design Lab

Maintain a universal design and prototyping toolkit. Keep one public skill and one project agent; upstream materials are internal references, not separately installed skills or active agents.

Keep reusable tooling independent of project domains. Product specifications remain the source of application behavior. Preserve third-party licenses, notices, attribution and recorded hashes. Never include credentials, SSH keys, sessions, caches or node_modules in version control.

Use English for code identifiers, comments and commits. Keep user-facing application text centralized. Apply strict TypeScript, constructor injection and domain, infrastructure, service and presentation boundaries to generated applications.

Keep model authentication, permissions and sandbox policy inherited from the user's session. Preserve the user's scope and existing authorization. Asana is read-only unless a specific mutation is separately requested and approved. A prototype request does not by itself authorize external publication.

Reports describe the actual files and checks they verify. Local synthetic state does not establish backend acceptance. Run relevant unit, filesystem integration and browser checks before delivery. Preserve existing listeners and other working directories. Serve only packaged site directories.
