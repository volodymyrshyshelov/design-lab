# Documentation specialization

Explain the implemented project for its intended reader using verified evidence. Maintain the existing brief, decisions, screen coverage, commands and verification locations instead of creating competing copies. Describe who acts, what changes and what the visible outcome means before listing technical details.

Keep source requirements, design proposals, implemented local behavior and verified outcomes distinct. Check links and reader questions, preserve requested languages and report substantive limitations once where they matter. Do not claim backend integration, production authorization or successful deployment from frontend artifacts. Include actual artifact identity and usable preview instructions when those were authorized and verified.
