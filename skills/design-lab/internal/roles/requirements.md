# Requirements specialization

Read the canonical brief and relevant existing product source. Identify actual application roles, journeys, fields, states, important alternatives and unresolved decisions. Preserve existing requirements and requested scope. Produce a small traceable screen/action map and explicit interface contracts that allow the other assignments to work independently.

Separate confirmed source behavior from design proposals. Ask the coordinator only about missing information that changes the product materially. An existing specification is evidence to read, not permission to invent its contents. Keep outputs in the assigned project files and report source locations.
