# Verification

Version 0.2 was checked on Linux with Node.js 24 and Chromium. The package suite passed 51 filesystem, HTTP, workflow, migration, bootstrap and resource-integrity checks. These include concurrent mutations, source and evidence invalidation, reviewer separation, interrupted-assignment recovery, and refusal to self-approve when native delegation is unavailable. Skill metadata, the single active agent definition and eight bundled reference modules were validated.

A clean project installation bootstrapped its own pinned runtime and exposed 20 tools through the actual stdio MCP protocol. Local diagnostics, a shadcn button lookup and a Magic UI registry request passed without separately installed component servers. Oversized input was rejected before forwarding. A pristine installation from the released v0.1 source migrated to one gateway, preserved unrelated settings and remained repeatable.

A small prototype adaptation created through the normal CLI passed strict TypeScript, seven service tests, a production build and portable packaging. Browser checks passed 150 direction/screen/role/viewport combinations, six offline file views and seven interactive scenarios. These scenarios cover record creation, reviewer handoff, confirmation, reload persistence, private-note projection, mobile dialog focus and offline input retention. Six desktop/mobile captures were inspected; ten additional focused interface, shortcut and artifact checks passed. No browser errors, console errors, external requests or overflow were observed in that scope.

That adaptation ran through the installed workflow with an actual native implementation worker and a separate reviewer started without inherited conversation history. The reviewer independently repeated TypeScript, the seven unit tests and six focused Chromium cases, inspected the source and captures, and reported no findings. Its current result and immutable evidence were submitted through the tools; `finish_run` completed and a subsequent `status` returned `acceptanceCurrent: true`. This validates a small real delivery cycle, not every possible project or worker configuration.

The source package exposes one skill and one active project agent. Vendored files and installed provenance retain their recorded hashes and license notices. Internal role prompts do not add discoverable skills or configured agents.

Native Windows/macOS execution and installation through the Codex plugin directory were not tested. The project installer is the validated setup route. These checks cover synthetic frontend behavior, not production authentication or external integrations. Dependency advisory notes are recorded in [third-party.md](third-party.md).
